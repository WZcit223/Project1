## 1. 框架功能

| 功能 | 价值 | 架构影响 | 优先级 | 依赖 |
|---|---|---|---|---|
| 自然语言意图智能体（NL intent agent，受限） | 面向管理层的"AI"入口；将请求转换为经过校验的运行配置 | 新增 `application.intent`；不改动 core | P1 | Application API、LLM 访问 |
| 轻量级 BI（透视表等） | 为运营用户提供探索性分析 | 仅 UI | P1 | Results API |
| 运行报告导出 | 与管理层共享结果 | `application.reporting` | P1 | Golden Path |
| 实验追踪 UI | 跨时间比较大量运行 | 使用现有运行存储（run store） | P1 | Run store |
| LLM 辅助生成器配置 | 根据需求更快地创建 schema/配置 | 提案 → 校验器路径；溯源字段 `proposal_source` | P2 | Synthetic API |
| `time_series` 的间歇性需求 / 零销量连续段选项 | 真实 M5 需求存在连续多天零销量（多为缺货），v1 负二项模型无法复现（真实子集中零销量天占 15%，合成数据为 4%） | 新的生成器版本或参数（如零膨胀、开/关状态切换）；无需改动引擎 | P1 | Phase 4 生成器、真实子集对比 |
| 新品冷启动处理 | v0.1 策略从不为没有销售历史的商品补货（已记录的限制） | 新的策略参数或预测插件（类比商品、品类先验）；无需改动引擎 | P2 | 商品属性、Phase 9 策略 |
| 高级生成器（Copula+、GAN、VAE、扩散模型、基于智能体） | 更高保真度的合成数据 | 仅新增生成器插件 | P2 | 真实数据验证方法 |
| 合成数据与真实数据保真度指标（层级 4） | 量化真实性、下游模型效用、隐私性 | 新增验证模块 | P2 | 真实 / 合作方数据 |
| 优化插件 | 在约束下求解最优补货参数 | `SimulationPlugin kind=optimization` | P2 | 策略比较 |
| 因果建模插件 | 基于因果效应的干预 / what-if 分析 | `SimulationPlugin kind=causal` | P2 | 因果图知识、数据 |
| 知识层 / 实体图谱 | 跨场景组织领域知识 | 位于 Dataset API 之后的 foundation 子包 | P3 | 用例 |
| 多模态数据（图像、文档、传感器波形） | 工业检测、维护日志 | foundation 扩展 | P3 | 场景需求 |
| 场景包的声明式流水线步骤 | 在多个场景包之间共享步骤日志 / 部分重跑 | `ScenarioPack.run` 可返回步骤列表或由步骤列表驱动；仅需改动运行器 | P2 | 第二个场景包 |
| 异步作业执行 | 长时间运行、更大数据集 | 运行已暴露 `status` | P2 | 规模需求 |
| React / 移动端 UI | 企业级用户体验 | 调用 Application API | P3 | 稳定的 API |
| 企业 IAM、多租户、云部署 | 生产使用 | 新增横切服务 | P3 | 产品化决策 |

## 2. 各场景的算法与数据需求（迈向完整能力）

将每个场景从框架验证案例转变为真实能力所需的条件。

### 2.1 仓储 / 库存（当前验证案例）

| 领域 | v0.1（原型） | 完整能力所需 |
|---|---|---|
| 需求数据 | M5 公开销售数据（门店级、观测销量） | 公司 SKU 级需求，含缺货标记（真实需求）、促销、退货 |
| 运营数据 | 合成的供应商、提前期、成本、初始库存 | 真实供应商主数据、含实际提前期的采购订单历史、成本结构、仓库容量、库存快照 |
| 预测 | 季节性朴素法（seasonal naive）+ LightGBM | 层级 / 概率预测（分位数）、促销与价格效应、需求截断修正、间歇性需求模型（Croston/TSB）、模型监控 |
| 库存模型 | 单级、缺货损失（lost sales）、按日 | 多级（DC ↔ 门店）、缺货回补/替代、容量与保质期约束、来自实际的 MOQ/箱规 |
| 策略 | 再订货点、安全库存、动态补货至目标水平（order-up-to） | 策略参数的随机优化 / 仿真优化、服务水平差异化（ABC/XYZ）、强化学习（研究） |
| 合成数据 | 规则、统计、时间序列生成器 | 基于公司数据验证保真度；用于数据共享的隐私保护生成器 |
| 验证 | 层级 1–3 | 层级 4：基于公司历史数据回测，与现行做法的试点对比 |

### 2.2 预测性维护（候选场景 2）

| 领域 | 所需 |
|---|---|
| 参考数据 | UCI Condition Monitoring of Hydraulic Systems（真实的多传感器试验台数据，含部件状态标签）；后续为公司传感器 + 维护日志 |
| 合成数据 | 传感器信号生成器（退化轨迹、故障注入、噪声）、故障事件生成器 |
| 算法 | 异常检测、剩余使用寿命估计、故障分类 |
| 仿真 | 维护策略仿真（运行至失效、预防性、基于状态）、停机与成本模型 |
| 框架影响 | 新增场景包；可能需要在 foundation 中支持多变量/高频信号 |

### 2.3 工业能源管理（候选场景 3）

| 领域 | 所需 |
|---|---|
| 参考数据 | UCI ElectricityLoadDiagrams2011–2014（370 个用户，15 分钟负荷）；后续为工厂电表数据、电价、天气 |
| 合成数据 | 负荷曲线生成器（天气、生产计划、价格场景） |
| 算法 | 负荷预测（复用 core 预测能力）、峰值检测 |
| 仿真 | 负荷转移 / 削峰策略、电价成本仿真 |
| 框架影响 | 新增场景包；支持日内时间索引 |
