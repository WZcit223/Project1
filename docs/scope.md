# Scope & Non-goals — v0.1

Status: **Draft for Gate 0 review** · 中文: [zh/scope.md](zh/scope.md)

> Architecture first, extensibility first, scenario validation second; productionization later.

## 1. In scope (v0.1)

**Foundation:** dataset ingestion, dataset schema, metadata, data catalog, data transformation,
M5 adapter, Synthetic Data Engine, provenance, entity representation.

**Simulation / intelligence:** demand forecasting (baseline + LightGBM), inventory simulation,
replenishment strategies (Reorder Point, Safety Stock, Dynamic), scenario modeling (4 scenarios),
strategy comparison.

**Application:** dashboard, data explorer, synthetic data configuration, scenario builder, simulation
execution, result visualisation, lightweight BI.

**Infrastructure (lightweight):** HTTP API, configuration, logging, versioning, plugin registry,
experiment/run metadata (SQLite), validation.

**Validation:** Levels 1–3 (engineering, synthetic-data structural, scenario behaviour). See
[validation.md](validation.md).

## 2. Explicit non-goals (v0.1)

This phase does **not** require or implement:

1. Proof that synthetic data is statistically, causally or economically equivalent to real industrial data.
2. Use of synthetic data for production decisions.
3. Production-grade deployment, SaaS, high availability, or cloud infrastructure.
4. Full causal modeling (interface compatibility only).
5. Advanced optimization (no optimizer; strategies are rule-based and compared).
6. Complex multi-agent systems (at most a limited intent → config translator, P1).
7. Kubernetes, microservices, Kafka / event streaming, Spark, distributed systems.
8. Vector databases or knowledge-graph infrastructure.
9. Full multimodal AI infrastructure.
10. Enterprise IAM / permission systems.
11. Industrial scenarios beyond Warehouse (Maintenance, Energy, Production are future plugins).
12. Large numbers of synthetic-data algorithms (exactly three in v0.1).
13. State-of-the-art forecasting (not an M5 competition solution).
14. React / Node build pipelines.
15. Validation with real enterprise data (Level 4).

Ideas outside scope go to [future-roadmap.md](future-roadmap.md), not into code.

## 3. Scope of the Warehouse validation case

| Included | Excluded (v0.1) |
|---|---|
| Daily, item × store demand | Intraday / hourly granularity |
| Single-echelon: store as stocking point, one synthetic supplier per item | Multi-echelon networks, DC ↔ store transfers |
| Lost sales | Backorders, substitution |
| Deterministic or stochastic lead time from synthetic data | Supplier selection / negotiation |
| Holding, ordering costs; stockout penalty reported separately | Full P&L, pricing decisions |
| 4 scenarios, 3 strategies, 2 forecast models | Optimizers, RL, causal effect estimation |
| Demo subset (default CA_1 × FOODS_3, top 50 items) | All 30,490 M5 series |

## 4. Data scope

| Data | Origin | In Git? |
|---|---|---|
| M5 sales, prices, calendar, events (subset) | Real, Kaggle M5 | **No** — local `data/raw/` only |
| M5-shaped test fixture | Synthetic (generated by project script) | Yes (small, labelled synthetic) |
| Inventory, supplier, lead time, purchase orders, warehouse, replenishment policy | Synthetic | Generated on demand; small samples may be committed |
| Scenario configs | Project-defined | Yes |
